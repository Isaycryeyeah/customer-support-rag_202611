# 简历描述与面试依据

面向 jd.md 的 Python/PyTorch、HF、向量检索、模型训练和评估工程岗位，建议项目名：**中文 3C 售后知识问答与重排序实验系统**。

可使用的三条描述：

- 基于 FastAPI、Streamlit 和 SQLite 实现中文售后 RAG，组合 BM25、FAISS 向量检索与 CrossEncoder；构建按证据组合分组的 449 题模拟评估集，区分真实 Recall、多证据命中、生成故障与安全路由，并接入日志与反馈闭环。
- 在 RTX 3060 Laptop 上优化重排序推理精度，89 题配对复测中检索＋重排 P95 从 172.5 ms 降至 65.4 ms（降低 62.1%），开发集排序指标一致，冻结测试排序持平；支持 CPU/GPU 精度适配及 Docker 演示。
- 使用 PyTorch/HF 对重排模型最后两层和分类头进行领域训练（约 1477 万可训练参数），构造 232 组、875 对样本，完成随机／困难负例、数据量与负例清洗对照；独立测试未显示采用收益，保留预训练模型并分析负例噪声和小样本局限。

如篇幅紧张，第三条保留训练设置和真实决策，不写“显著提升”。若面试强调模型效果，可补充 test_v1 的 Hybrid 与预训练重排 MRR@10 为 0.8504／0.9342；这属于预训练组件对照，不能写成微调收益。

## 面试准备

| 问题 | 可展示证据 |
|---|---|
| 为什么要重排？ | 四种检索对照、同一候选池和多 gold Recall，evaluation_baseline.md |
| 为什么保留 20 候选？ | dev 10/20/30 搜索，召回、拒答和延迟约束 |
| 62.1% 如何测量？ | 同题配对、顺序随机、CUDA 同步，89 题×3 次；不含 LLM |
| 为什么训练没提升？ | 预训练基线较强、数据少、困难负例潜在相关；审计和清洗后仍未越过采用门槛 |
| 训练了什么？ | BCEWithLogitsLoss、AdamW、最后两层与分类头，非全参数、非 LoRA |
| 如何隔离测试？ | 分组 manifest、数据／代码／权重哈希；test_v1、v2、v3 各自阶段冻结 |
| 用户反馈改了什么？ | 四题评分留存、域外不转人工、隐私路由一致、来源归并、安全模板 |
| 工程化做到哪？ | 干净环境、Docker 真实 SDK、HTTP 503、日志迁移；工单仍是建议 |

不写：真实企业售后数据、500 条人工审核训练问题、生产级服务、完整派单、安全准确率 100%、微调后效果提升、LoRA／全参数训练或已开源（尚未发布）。

# 正确性修复报告

日期：2026-10-31。状态：主要代码及离线回归已完成，真实后端成功生成的验收仍受网络环境限制。

## 修复内容

1. 生成返回 `GenerationResult`，包括成功标志、模型、用量、尝试次数、结束原因、错误类别和耗时；空输出、截断和 API 故障不会成为普通生成答案。
2. SDK 内部重试关闭，应用层限制尝试次数，并根据剩余预算传入调用超时。该预算控制新调用和重试，不将 HTTP 客户端的分阶段超时误称为严格的进程级截止时间。
3. 高风险识别后直接使用确定性安全响应，跳过检索与生成；增加有限的否定表达处理，仍保留关键词规则的泛化限制。
4. 无依据、安全风险、业务审核和服务故障分别记录人工处理原因；工单建议与响应使用同一最终状态，不声称已经派单。
5. API 故障返回 503 和结构化响应；前端保留故障提示及人工处理建议，支持对对应日志反馈。
6. SQLite 采用添加字段的迁移方式，保留原问答及反馈 ID；新增请求 ID、回答类型和版本化证据。
7. 索引失配时重建，搜索 k 超过片段数、空知识库及空重排序候选有明确边界处理。
8. 评估中剔除故障模板的生成质量得分，区分 Hit@k 与 Recall@k，避免将规则识别准确率等同于最终回答安全性。

## 验证

34 项自动测试全部通过，覆盖正常生成、确定性安全分支、否定表达、低置信度、空输出、截断、连接失败、超时、限流、鉴权失败、重试预算、HTTP 状态、反馈、旧库迁移、索引边界、评估口径、分组隔离和页面故障展示。完整结果见 `data/eval/runs/correctness-tests.xml`。

真实 HTTP 请求记录见 `data/eval/runs/correctness-http/report.json`：

| 请求 | 状态 | 结果 |
|---|---|---|
| `/ready` | 200 | 模型与知识库已加载，返回知识库哈希 |
| 手机保修咨询 | 503 | SDK 连接失败，明确 `service_unavailable`；响应与工单均建议人工处理 |
| 电池鼓包问题 | 200 | `safety_refusal`，无生成调用 |
| 天气问题 | 200 | `low_confidence`，转人工状态一致 |

上述检查只证明故障、安全和无依据分支正确，不证明当前后端已成功调用真实模型。正常生成的 HTTP 状态通过依赖受控的测试验证，不作为真实在线生成证据。

原有 25 条规则识别样本全部通过，原始指标保存在 `data/eval/runs/safety-rules/report.json`；不能据此宣称系统在任意安全问题上均可靠。提示注入和否定表达的少量回归样本也不能替代全面的安全评估。

- 规则不能覆盖所有口语表达、间接危险请求和复杂否定。
- 暂无在线正常生成验收和独立测试集；计划中的阶段 1 完整验收与 M1 均未标记完成。

新数据使用 `plan.md` 中的字段规范。问题分组后划分 train/dev/test，同一问题改写保持同组。测试集在方案选择后统一运行，不用来调参。相同知识库可出现在多个划分中，结论仅表示已知知识库上的新查询表现。

```powershell
python scripts/prepare_eval.py --input data/eval/annotations.jsonl --output data/eval/v1
```

脚本拒绝重复 query_id、规范化后完全相同的问题、跨集合 group_id、非法 gold 和无答案的伪造 gold。字符相似问题给出复核提示；该检查无法保证语义无泄漏。默认 manifest 标记为草稿；完成实际标注及相似问题复核后，才能使用 `--reviewed` 创建新的已审核版本。没有标注文件时不能执行上述命令。

## 检索指标

- Hit@k：前 k 条至少命中一个相关片段。
- Recall@k：命中的唯一相关片段数 / 全部标注相关片段数。
- MRR@10：首个正确片段在前 10 条内的倒数排名。
- nDCG@5：使用二值相关性评价前 5 条排序，多 gold 时与 Hit@k 分开解释。
- 无答案问题不进入上述相关性指标分母，单独评估拒答。

比较重排序时固定上游候选序列，并报告候选召回；不能将上游漏召与候选内排序错误混为一谈。计分前应审核 gold 完整性。

## 生成、拒答与故障

`answer_type=service_unavailable` 为服务故障，不能获得成功生成、格式或要点分。生成指标同时报告全量分母和成功生成子集，子集为空时质量指标为 null，不能记为 0% 或 100%。mock 运行只用于回归，不能作为真实生成证据。

词面要点匹配只是辅助指标，不能证明语义正确。人工复核采用以下尺度，并保存逐题依据：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 事实与依据 | 存在错误／无依据关键结论 | 部分正确但有遗漏／歧义 | 关键结论正确且有文档支持 |
| 要点完整性 | 缺失关键要点 | 部分覆盖 | 必要要点全部覆盖 |
| 引用支持 | 无效／不存在的来源 | 来源相关但支持不足 | 每个关键结论有对应证据 |

危险指导、越权承诺单独标记为关键失败，不用平均分掩盖。安全规则测试仅报告风险识别；最终回答还需核对确定性安全分支和实际文本。检查无答案拒答 precision/recall，以及应答却拒答、无依据仍回答比例时，应同时报告原始计数；没有相应类别时指标为 null。

## 性能实验

```powershell
$env:HF_HUB_OFFLINE='1'
$env:TRANSFORMERS_OFFLINE='1'
python scripts/benchmark.py --output data/eval/runs/unique-run-name --repeats 3
```

该入口不调用 LLM，默认使用历史开发数据，仅支持开发实验。复用同一次混合检索的候选序列，截取不同长度重排，随机化查询和配置执行顺序，预热后测量，CUDA 场景计时同步设备。

质量每题计算一次，不通过重复测量扩大质量样本数；耗时记录全部重复。候选数量、数据哈希、模型 revision、设备、线程数、测量次数及逐题结果一起保存。冷启动另报，重排序延迟不得表述为完整问答延迟。在线模型 token 成本需使用实际调用量与注明日期的价格表计算，目前未宣称已有成本优化结果。
